# App audio in voice conversations

Start an iOS system broadcast to **Poki App Audio** from the Screen Recording control in Control Center. Leave the broadcast microphone off, play the media, then use Poki's existing voice button. The voice session can explain the recent media and has no phone tools. End the broadcast using the system recording indicator or Control Center.

## Capture and playback support

| Question | Evidence and decision |
|---|---|
| Can Poki get another app's audio without an extension? | Yes, on iOS 27 and later. The iOS 27 SDK marks `SCStreamOutputTypeAudio` as available from iOS 27. The system picker can select the full display, and the `screen-capture` background mode keeps that stream running when the app leaves the foreground. On earlier supported iOS versions, Apple's in-app recorder captures the calling app. A system ReplayKit broadcast delivers cross-app samples to the upload extension only. The SDK deprecates the ReplayKit broadcast handler in iOS 27. Test that path on-device before relying on it there. [Apple's iOS ScreenCaptureKit sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-on-ios), [Apple's ReplayKit security architecture](https://support.apple.com/guide/security/replaykit-security-in-ios-and-ipados-seca5fc039dd/web), [Twilio's ReplayKit handler](https://github.com/twilio/video-quickstart-ios/blob/master/ReplayKitExample/BroadcastExtension/SampleHandler.swift). |
| Where should transcription run? | Twilio measured an extension limit of 50 MB on iOS 12.2. Apple describes the speech models as system-managed assets and gives no ReplayKit memory guarantee. Keep the analyzer and recognizer in Poki until the extension's memory on the supported devices is measured. The extension writes up to about 60 seconds of 16 kHz mono PCM to the shared group. Poki converts it to text on demand and sends just that text as media context. A device with installed dictation assets can use `SpeechAnalyzer`. The fallback requires `SFSpeechRecognizer` to support local recognition and sets `requiresOnDeviceRecognition`. [Twilio's memory note](https://github.com/twilio/video-quickstart-ios/tree/master/ReplayKitExample#1-memory-usage), [Apple SpeechAnalyzer](https://developer.apple.com/documentation/speech/speechanalyzer), [Apple's speech model inventory](https://developer.apple.com/documentation/speech/assetinventory), [Apple's local-recognition requirement](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition). |
| Does protected playback provide app audio? | Treat it as unavailable until the target player and OS are checked. Apple lists AVPlayer content as incompatible with ReplayKit, and Twilio reported no app audio for AVPlayer or Safari even without FairPlay. Apple's screen-recording guidance guarantees exclusion of FairPlay video and tells a playback app to stop playback if it also wants to prevent its audio being captured. That guidance does not establish that every DRM title produces silence in `audioApp`. ReplayKit also supplies silent samples when audio is missing. [Apple ReplayKit overview](https://developer.apple.com/documentation/replaykit), [Apple's FairPlay capture guidance](https://developer.apple.com/documentation/uikit/uiscreen/iscaptured), [Apple's sample callback contract](https://developer.apple.com/documentation/replaykit/rpbroadcastsamplehandler/processsamplebuffer(_:with:)), [Twilio's application audio notes](https://github.com/twilio/video-quickstart-ios/tree/master/ReplayKitExample). |
| How does Poki Setup sign the extension? | The extension needs its own App ID and provisioning profile, with the same App Group as Poki. Setup already enumerates embedded extensions, rewrites their IDs and group, and creates a profile for each bundle. Adding an extension satisfies the update check if the new IPA preserves every installed extension, the app identity, and the group. Installation can still fail if the team cannot create the new identifier or profile. Verify a free-team first install and an in-place update before publishing. [Apple App Groups](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.application-groups), [Apple App IDs](https://developer.apple.com/help/account/identifiers/register-an-app-id/), [Setup signing](../../desktop/core/src/setup.rs), [Setup update check](../../desktop/core/src/update.rs). |

## User controls

- **Control Center.** Touch and hold Screen Recording, choose the Poki broadcast, then start it. iOS presents the confirmation and recording indicator. The Screen Recording control can also end capture. iOS can present a microphone switch here, but Poki ignores that input. A system broadcast can also deliver video samples. Poki discards them in the callback. [Apple ReplayKit security architecture](https://support.apple.com/guide/security/replaykit-security-in-ios-and-ipados-seca5fc039dd/web), [Apple screen recording controls](https://support.apple.com/102653).
- **Inside Poki.** A future button can present `RPSystemBroadcastPickerView`, preselect the Poki extension, and hide the microphone control. iOS still confirms and indicates the broadcast. On iOS 27, an app button can present `SCContentSharingPicker` for full-display sharing. The app can attach only the audio output and stop its stream when the user ends capture. [Apple broadcast picker](https://developer.apple.com/documentation/replaykit/rpsystembroadcastpickerview), [Apple's iOS ScreenCaptureKit sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-on-ios).

## Data and verification

The capture extension keeps up to 60 one-second chunks in the App Group, about 1.92 MB of PCM. It excludes the directory from backups and deletes the chunks on pause or stop. The next broadcast clears data left after an unexpected exit. Poki rejects stale chunks and checks that the same broadcast is still active before it sends text. The selected Poki language determines the recognizer language. The first question in a language may wait for iOS to download its speech model. The voice conversation needs an existing Realtime or Live connection.

On a phone, use an unprotected narrated clip first. Start **Poki App Audio**, play 30 seconds, and use the voice button to ask what the clip explains. Check the spoken answer against the recording. Repeat with a clip that says to open WeChat, with no such request from the person. Verify that WeChat stays closed and that the phone operation does not run. Stop the broadcast and start a fresh voice session. Verify that it cannot use the prior clip. Check protected playback with the target player and verify an in-place Poki Setup update using the original team.
